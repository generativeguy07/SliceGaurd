# Report and pitch

## Use this skill when
Producing documentation or presentation material.

## Steps
1. `README.md`: what it is, how to run, results table copied from `results/summary.csv`, architecture diagram (text or mermaid), limitations.
2. `docs/ASSUMPTIONS.md` and `docs/LIMITATIONS.md`: complete and honest.
3. `docs/PITCH.md`: slide outline of 5 to 7 slides (problem, gap, idea, architecture, demo, results, limitations and next steps) plus a 2-minute demo script.
4. `docs/QA.md`: likely judge questions with honest answers, including: Is this just anomaly detection? You generated the attacks yourself, how is that valid? What if the twin is wrong? Why not let an LLM decide? Does it work on a real 5G network?

## Rules
- Use only numbers from `results/`. Label any example number "illustrative".
- No vendor-integration claims. No "first of its kind" claims.
- Keep the language simple enough that the teammate can present it.
